# 【Code with SOLO】用 SOLO 搭建 GitInsight — 一键可视化分析 Git 代码贡献，让团队协作数据一目了然

## 一、摘要

用 TRAE SOLO 从零搭建了一个 **Git 代码贡献可视化分析工具（GitInsight）**——只需在终端运行一条命令，将输出粘贴到工具中，即可自动生成包含贡献热力图、提交趋势、贡献者排行、时间分布等 6 大维度的可视化分析报告。纯前端实现，无需安装，打开即用。

## 二、背景

我是一名开发者，在日常工作中经常需要回答这些问题：

- 这个项目谁贡献最多？
- 团队的提交频率如何？有没有人在摸鱼？
- 代码变更集中在哪些时间段？
- 最近一个月项目进展如何？

虽然 GitHub 自带贡献图，但它只能看个人的，无法分析整个仓库的团队贡献。市面上的 Git 分析工具（如 GitStats、GitLab Analytics）要么需要安装配置，要么依赖特定平台。

我想要一个**零安装、打开即用、支持任意 Git 仓库**的轻量分析工具。于是用 SOLO 一次对话搞定了。

## 三、实践过程

### 第一步：确定产品形态

我明确了几个设计原则：

1. **零安装**：纯 HTML/CSS/JS，浏览器直接打开
2. **零依赖（除 CDN）**：不需要 npm install，不需要构建工具
3. **输入简单**：一条 git 命令 + 粘贴
4. **输出丰富**：多维度可视化图表

### 第二步：技术方案

| 模块 | 技术 | 说明 |
|------|------|------|
| UI 框架 | 原生 HTML/CSS | 零依赖，GitHub Dark 风格 |
| 图表库 | Chart.js (CDN) | 折线图、柱状图、雷达图 |
| 热力图 | Canvas 2D 自绘 | 类 GitHub 贡献日历 |
| 数据解析 | 正则表达式 | 解析 git log 格式化输出 |

### 第三步：核心模块实现

**1. Git Log 解析引擎**

这是最核心的部分。用户在终端运行：
```bash
git log --all --pretty=format:"%H|%an|%ae|%aI|%s" --shortstat
```

解析引擎用正则匹配每一行，提取 commit hash、作者、时间、消息，以及 shortstat 中的文件变更数、新增行数、删除行数：

```
输入：a1b2c3d4...|张三|zhangsan@mail.com|2026-04-15T14:30:00+08:00|feat: 新增登录功能
      3 files changed, 42 insertions(+), 10 deletions(-)

解析 → {
  hash: "a1b2c3d",
  author: "张三",
  date: Date对象,
  message: "feat: 新增登录功能",
  additions: 42,
  deletions: 10,
  filesChanged: 3
}
```

**2. 贡献热力图（Canvas 自绘）**

完全用 Canvas 2D API 手绘，模拟 GitHub 的贡献日历：
- 52 周 × 7 天的方块网格
- 5 级绿色深度映射提交频率
- 月份标签 + 星期标签
- 自动计算最近一年的数据范围

**3. 四维图表（Chart.js）**

- 📈 **提交趋势**：按周统计的折线图，看项目活跃趋势
- 🏆 **贡献者排行**：水平柱状图，Top 10 贡献者
- ⏰ **时间分布**：24 小时柱状图，发现团队的编码时间段
- 📅 **星期分布**：雷达图，工作日 vs 周末的贡献对比

**4. 报告导出**

一键导出 Markdown 格式的分析报告，包含概览统计、贡献者排行、最近提交记录。

### 第四步：用 SOLO 的过程

整个开发过程只用了 **一次对话**，我的 Prompt 大致是：

> "帮我创建一个 Git 代码贡献可视化分析工具。纯前端 HTML/CSS/JS 实现，GitHub Dark 风格 UI。功能：1) 解析 git log --pretty=format 输出；2) Canvas 绘制贡献热力图；3) Chart.js 绘制提交趋势、贡献者排行、时间分布、星期分布 4 个图表；4) 统计卡片显示总提交数、贡献者数、活跃天数、日均提交；5) 支持导出 Markdown 报告；6) 提供示例数据一键体验。"

SOLO 一次性生成了完整的代码，结构清晰，逻辑正确。我只做了少量调整（合并 ES Module 为单文件以兼容直接打开）。

### 第五步：踩坑记录

1. **ES Module 兼容性**：初始用了 `export/import` 语法，但直接打开 HTML 文件时不支持。解决方案：合并为单文件，去掉模块语法
2. **git log 格式解析**：`--shortstat` 的输出是多行的，需要正确处理 commit 行和 stat 行的对应关系
3. **热力图日期对齐**：需要将日期对齐到周日开始，否则周数会错位
4. **Chart.js 实例管理**：切换数据时需要先销毁旧图表实例，否则会内存泄漏

### 使用方式

1. 打开 `index.html`
2. 在终端运行 `git log --all --pretty=format:"%H|%an|%ae|%aI|%s" --shortstat`
3. 粘贴输出 → 点击"开始分析"
4. 查看可视化报告 → 可导出 Markdown

或直接点击"加载示例数据"快速体验。

## 五、效果与总结

### 提效数据

| 指标 | 传统方式 | 用 SOLO |
|------|---------|---------|
| 开发时间 | 1-2 天 | **1 次对话（约 30 分钟）** |
| 代码量 | ~1500 行手写 | SOLO 生成 + 微调 |
| 使用门槛 | 需安装 GitStats 等工具 | **浏览器打开即用** |

### 思考与收获

1. **小工具大价值**：不需要复杂的项目才能参赛，解决真实痛点的小工具同样有竞争力
2. **SOLO 的全栈能力**：从 UI 设计到数据解析到可视化，SOLO 都能一次性搞定
3. **纯前端的优势**：零安装、零配置、即开即用，分享一个 HTML 文件就能让任何人使用
4. **可视化让数据说话**：同样的 git log 数据，可视化后信息密度和可读性提升了 10 倍

### 适用场景

- 🏢 **团队管理**：快速了解团队成员的贡献情况
- 📊 **项目复盘**：回顾项目周期内的开发节奏
- 👤 **个人总结**：生成年终/季度个人开发报告
- 🎯 **招聘评估**：分析候选人的 GitHub 开源贡献模式

> 💡 **一句话总结**：用 SOLO 30 分钟搭建了一个让 Git 数据"开口说话"的可视化工具，零安装、即开即用，这就是 AI 赋能开发者生产力的最好证明。
