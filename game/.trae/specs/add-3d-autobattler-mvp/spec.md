# 3D PVE 自走棋肉鸽 MVP Spec

## Why
用户希望开发一款融合 PVE、肉鸽（Roguelike）、自走棋（金铲铲之战式）和海克斯科技（Hex Augments）机制的 3D 游戏。当前工作区为空，需要从零搭建一个最小可玩原型（MVP），用于验证核心玩法循环的趣味性，便于后续扩展。

## What Changes
- 初始化 Three.js + TypeScript + Vite 项目骨架
- 实现 3D 棋盘渲染（方格网格，俯视斜角视角）
- 实现单位系统（4 种基础单位，含 HP/攻击/攻速/移速属性）
- 实现商店系统（每回合随机刷新 5 个单位，金币购买）
- 实现经济系统（基础金币 + 利息 + 连胜/连败奖励）
- 实现战斗系统（单位自动寻敌、移动、攻击，30 秒超时）
- 实现玩家 HP 与胜负判定（输方扣血，归零游戏结束）
- 实现海克斯科技系统（偶数回合 3 选 1 强化）
- 实现肉鸽循环（关卡递进，难度上升，失败重开）
- 实现基础 UI（金币/HP/回合 HUD、商店、棋盘交互、强化选择面板）

## Impact
- Affected specs: 无（全新项目）
- Affected code: 全新代码库，将在 `/workspace` 下初始化；无既有代码冲突

## ADDED Requirements

### Requirement: 项目骨架
系统 SHALL 提供 Three.js + TypeScript + Vite 项目骨架，可通过 `npm install && npm run dev` 启动开发服务器，并在浏览器中加载 3D 场景。

#### Scenario: 启动开发服务器
- **WHEN** 用户运行 `npm run dev`
- **THEN** Vite 在 `http://localhost:5173` 提供页面
- **AND** 浏览器加载后显示一个非空 3D 场景（含相机、灯光、地面）

### Requirement: 3D 棋盘
系统 SHALL 渲染一个 6 列 × 4 行的方格棋盘（玩家区域 6×2，敌方区域 6×2），采用俯视斜角视角，玩家与敌方区域用不同颜色区分。

#### Scenario: 棋盘渲染
- **WHEN** 游戏启动进入战斗准备阶段
- **THEN** 场景中显示 24 个格子组成的 3D 棋盘
- **AND** 玩家区域格子为蓝色调，敌方区域格子为红色调

### Requirement: 单位系统
系统 SHALL 提供 4 种基础单位（战士/弓手/法师/坦克），每种单位有 HP、攻击力、攻击速度、移动速度、攻击范围属性，并以不同颜色和形状的 3D 几何体在场景中表示。

#### Scenario: 单位属性可见
- **WHEN** 玩家悬停或选中一个单位
- **THEN** 显示该单位的名称和核心属性

#### Scenario: 单位放置到棋盘
- **WHEN** 玩家从备战区拖拽或点击单位后点击玩家区域空格
- **THEN** 该单位以 3D 模型出现在指定格子
- **AND** 备战区对应槽位清空

### Requirement: 商店与经济
系统 SHALL 在每回合开始时随机刷新 5 个单位到商店，玩家拥有金币可购买；玩家每回合获得基础金币（5 + 当前回合数）和利息（每 10 金币 1 利息，上限 5）。

#### Scenario: 购买单位
- **WHEN** 玩家点击商店中的单位且金币 ≥ 单位价格（默认 2 金币）
- **THEN** 金币扣除单位价格
- **AND** 单位进入备战区第一个空位
- **AND** 商店对应槽位标记为已售

#### Scenario: 刷新商店
- **WHEN** 玩家点击刷新按钮且金币 ≥ 2
- **THEN** 金币扣除 2，商店重新随机生成 5 个单位

### Requirement: 战斗系统
系统 SHALL 在玩家点击"开始战斗"后进入战斗阶段，所有单位自动寻敌、移动并攻击，直到一方全军覆没或战斗超时（30 秒）。

#### Scenario: 自动战斗
- **WHEN** 战斗阶段开始
- **THEN** 每个单位寻找最近的敌方单位
- **AND** 未在攻击范围内的单位向目标移动
- **AND** 在攻击范围内的单位按攻击速度间隔造成伤害

#### Scenario: 单位死亡
- **WHEN** 单位 HP ≤ 0
- **THEN** 该单位从棋盘移除，不再参与战斗

#### Scenario: 战斗超时
- **WHEN** 战斗持续 30 秒未分胜负
- **THEN** 战斗结束，按存活单位数判定胜负

### Requirement: 胜负与 HP
系统 SHALL 在战斗结束时根据胜负扣除玩家 HP：玩家战败时，按敌方存活单位数 × 2 扣除 HP；玩家初始 100 HP。

#### Scenario: 玩家战败扣血
- **WHEN** 战斗结束且玩家方全灭或存活单位少于敌方
- **THEN** 玩家 HP 按敌方存活单位数 × 2 扣减
- **AND** 显示扣血动画/提示

#### Scenario: 玩家胜利
- **WHEN** 战斗结束且玩家方有存活单位、敌方全灭
- **THEN** 玩家 HP 不扣减，获得战斗奖励金币

#### Scenario: 游戏结束
- **WHEN** 玩家 HP 降至 0
- **THEN** 显示"游戏结束"界面
- **AND** 提供重新开始按钮

### Requirement: 海克斯科技
系统 SHALL 在第 2、4、6... 偶数回合结束时弹出 3 选 1 强化面板，玩家选择 1 个强化后效果持续整局游戏；强化库至少包含 6 种不同强化。

#### Scenario: 选择强化
- **WHEN** 偶数回合战斗结束
- **THEN** 弹出 3 个随机且不重复的强化选项
- **WHEN** 玩家选择其中 1 个
- **THEN** 强化立即生效，进入下一回合

### Requirement: 肉鸽循环
系统 SHALL 让玩家在每场战斗后进入下一关卡，敌方单位数量与属性随关卡递增（每 2 回合敌方 +1 单位，每回合敌方属性 +10%），直到玩家 HP 归零结束整局。

#### Scenario: 关卡递进
- **WHEN** 一回合结束（含强化选择完成）
- **THEN** 回合数 +1
- **AND** 敌方阵容按规则增强
- **AND** 玩家进入下一回合的准备阶段

#### Scenario: 重新开始
- **WHEN** 玩家在游戏结束界面点击"重新开始"
- **THEN** 重置所有状态（HP、金币、回合、强化、单位），回到第 1 回合准备阶段

### Requirement: 基础 HUD 与 UI
系统 SHALL 在屏幕上显示 HUD（金币、HP、回合数）和交互面板（商店、备战区、强化选择、战斗按钮）。

#### Scenario: HUD 信息可见
- **WHEN** 游戏处于任意阶段
- **THEN** 屏幕顶部或角落显示当前金币、HP、回合数

#### Scenario: 阶段切换提示
- **WHEN** 阶段在准备/战斗/结算之间切换
- **THEN** UI 明确指示当前阶段并启用/禁用对应操作
